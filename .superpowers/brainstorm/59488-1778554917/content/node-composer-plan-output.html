What should Plan do?

Same node composer, three different levels of commitment before execution starts.

A. Draft child graph only
Root
Build cross-platform release UX
1. Inspect packaging path
2. Build first-run chooser
3. Verify startup
Nothing runs until user approves the drafted children.

Plan creates editable pending nodes

Safest and cleanest. The graph expands, but execution remains stopped until the author confirms.

B. Plan plus complexity labels
Root High
Packaging adapter Med
Install prompt Low
UI smoke tests Med
High-complexity nodes show a Break down action.

Plan estimates decomposition pressure

The planner marks nodes Low, Medium, or High so the user knows where to recurse again.

C. Plan auto-runs simple nodes
Root planning complete
Docs node: running
Code node: waiting approval
Test node: queued
Simple children may begin automatically under a configured budget.

Plan can start bounded execution

Fastest, but easier to surprise the author. Requires strong budgets and visible pause points.

Recommendation

Use B as the default behavior, with A as the safety rule: Plan expands into editable pending nodes, labels complexity, and never starts execution until explicitly approved.
