    1. Extend `RunConfiguredAgentInput` in `agent-runner.ts`:
       ```typescript
       nodeBinding?: {
         toolAllowlist?: string[];
         purposeTiers?: Partial<Record<LanguageModelPurpose, string>>;
       };
       ```
       Before `runRecursivePrompt`, if `nodeBinding.toolAllowlist` is non-empty, filter `input.agent.tools` to allowed names (same logic as `RecursiveLanguageModel.toolsForTask`). Wrap the `PurposeRoutingLanguageModel` so each `complete()` call: when no explicit model override and `purpose` is set, apply `overrideModelSelection: nodeBinding.purposeTiers[purpose]` via existing model-provider path.

    2. Implement `executeGraph(session: InteractiveExecutionSession, input: GraphExecutorInput)`:
       - Read `const graph = session.snapshot().graph`
       - Compute `order = topologicalExecutionOrder(graph)`
       - Track `failedNodeIds = new Set<string>()`
       - For each `nodeId` in order:
         a. If any ancestor (walk parentId chain) is in `failedNodeIds`, call `session.control.updateNodeStatus?.(nodeId, "failed", { code: "blocked_by_failure", message: "Blocked: ancestor node failed" })` and continue (do NOT execute)
         b. If `session.control.isCancelled()`, break
         c. Load node from graph; skip if status is `skipped` or `cancelled`
         d. **Bind time (EXEC-02):** `const agentId = node.expertAgentId ?? "default"`; `resolveAgent(input.registry, agentId)` — catch and map to `updateNodeStatus(nodeId, "failed", { code: "invalid_agent", message })` then add to failedNodeIds
         e. **Runtime validation (EXEC-03):** if `node.expertRuntime` is not `"single-pass"` or `"rlm"`, fail with `{ code: "invalid_runtime", message: "Runtime mode must be single-pass or rlm." }` — do NOT default missing runtime to rlm
         f. Build `ExecutionGraphNode` from session node; call `session.control.waitForNodeApproval?.(node)` if present. If decision status is `skipped`/`cancelled`, respect and continue
         g. `session.control.updateNodeStatus?.(nodeId, "running")`
         h. Build prompt via `buildExecutionPrompt(node, ancestors)`
         i. Filter tools via allowlist into `boundAgent = { ...agent, tools: filteredTools }`
         j. **single-pass:** create PurposeRoutingLanguageModel with node purpose tiers; call `model.complete([{role:"system", content: boundAgent.systemPrompt}, {role:"user", content: prompt}], { purpose: "solve" })` once; store result in logger; mark `completed`
         k. **rlm:** call `runConfiguredAgent({ prompt, agent: boundAgent, agentSource: "override", nodeBinding: { toolAllowlist, purposeTiers }, execution: session.control, ...rest of input })`; mark `completed` on success
         l. On error: `updateNodeStatus(nodeId, "failed", { message, failureCategory: "execution" })`; add to failedNodeIds
       - Do NOT call `selectAgent` anywhere in this module.

    3. Expose effective runtime metadata: before run, if session node supports it, set `node.effectiveModel` or publish execution event with `{ expertAgentId, expertRuntime }` in message for UI consumption (use existing publish via updateNodeStatus detail.message like `Running as ${agentId} (${runtime})`).
  </action>
