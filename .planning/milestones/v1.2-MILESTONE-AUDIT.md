## Integration assessment

1. **BLOCKER — MODL-05 / config:** `resolveRuntimeConfig` uses `const runtime = { ...DEFAULT_PROJECT_CONFIG.runtime, ...config.runtime, ...overrides }`. A CLI-provided `overrides.qualityLoop` object **replaces** the merged `qualityLoop` wholesale, so `runtime.qualityLoop.phaseModels` from YAML can be **silently dropped**. Fix: deep-merge `qualityLoop` (and nested `phaseModels`) when applying overrides; add a regression test (YAML `phaseModels` + `--quality-loop`).
2. **WARNING — UXQL / VERF-02:** `rlm ui` serves the interactive session and static UI; it does not invoke `runConfiguredAgent` / `runRecursivePrompt` in the same process. Loop metadata in the browser is consistent with **tests and session wiring** but not a single packaged “Browser runs the full loop” E2E unless a harness attaches engine + session.
3. **WARNING — UXQL-04:** `checkManualDecision` runs at iteration/phase boundaries; stop/accept during an in-flight LLM call takes effect after the phase returns.
4. **Non-requirement:** Optional doc update for quality-loop HTTP routes.

Primary milestone **user story** (“no silent failures”) is violated for **MODL-05** in the YAML+CLI combination because overrides disappear without an explicit error.
