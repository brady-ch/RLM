# Plan 29.1-01: Wire session save/reopen memory binding

## Goal

Close audit gaps by binding runtime memory and vector state to saved session bundles and restoring them on reopen.

## Tasks

### Wave 1 — Session memory bridge

1. Add `src/application/session-memory-bridge.ts` with:
   - `buildSavedSessionPayload(snapshot, runId, memoryStore, vectorIndex)` — export live memory/prefs/vector
   - `restoreSessionMemory(runId, payload, memoryStore, vectorIndex)` — import bundled memory on reopen
   - `readRunIdFromPayload(payload)` — extract runId with backward-compatible fallback

2. Add `FileMemoryStore.restoreSessionData()` for bulk import of scopes/episodic/audit/packets.

3. Add `FileVectorIndex.mergeSessionRecords(sessionId, records)` to merge without clobbering other sessions.

### Wave 2 — Runtime wiring

4. Update `control-server.ts`:
   - Accept `sessionRuntime: { runId, memoryStore, vectorIndex, getMemory, setMemory }`
   - Save uses `buildSavedSessionPayload`
   - Open calls `restoreSessionMemory` then rebinds memory resolver

5. Update `index.ts`:
   - Use saved runId when `--open-session` provided
   - Block CLI open when verification !== complete (exit 1, no restore)
   - Pass sessionRuntime to control server

### Wave 3 — Async indexing

6. Update `SemanticMemoryIndex`:
   - Remove sync rebuild from `search()`
   - Add `enqueueRebuild()` fire-and-forget
   - Hook enqueue from `MemoryResolver` after writes

### Wave 4 — Tests

7. Add tests in `tests/session-memory-bridge.test.ts`:
   - Save exports live scopes/episodic
   - Restore rebinds memory under saved runId
   - CLI/API parity on unsafe open (via bridge + store tests)
   - Vector merge preserves other sessions
   - Search does not block on empty index

8. Run `npm test` — all tests pass.

## Verification

- Saved session bundle contains non-placeholder memory and vector sections when runtime has data
- Reopen with `--open-session` uses saved runId and `/api/memory` shows restored episodic/scopes
- CLI refuses non-complete verification before restore
- `SemanticMemoryIndex.search()` returns empty without synchronous rebuild

| Criterion | Evidence |
