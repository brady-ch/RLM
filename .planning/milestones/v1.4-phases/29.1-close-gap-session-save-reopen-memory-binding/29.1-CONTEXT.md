# Phase 29.1: Close gap: session save/reopen memory binding - Context

**Gathered:** 2026-05-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Close milestone audit gaps for session save/reopen memory binding. Wire live memory and vector state into saved session bundles, rebind runtime memory on reopen using persisted runId, align CLI unsafe-open behavior with API 409 gate, and make vector indexing non-blocking on the retrieval hot path.

**In scope:** SESS-01, SESS-04, MEM-04, SURF-01/02/03 partial gaps, RETR-02, RETR-05 from `.planning/v1.4-MILESTONE-AUDIT.md`.

**Out of scope:** PREF-02 permanent lifetime UI, runState section population, multi-machine sync.

</domain>

<decisions>
## Implementation Decisions

### Session identity and memory binding
- **D-01:** Persist `runId` in the saved session `memory` section (version 2 envelope). On reopen, reuse saved `runId` instead of generating a new one.
- **D-02:** On save, export live session-scoped memory: scopes, episodic log, audit trail, packet metadata, and project-preferences scope content from `FileMemoryStore` for the active runId.
- **D-03:** On reopen, import bundled memory back into the store under the saved runId before starting the control server so `/api/memory` reflects restored session memory.

### Vector index persistence
- **D-04:** On save, snapshot vector index records filtered to the active runId plus index manifest metadata into the `vectorIndex` section.
- **D-05:** On reopen, merge saved vector records for the runId into the global index file (replace records with same sessionId, keep others).

### Unsafe continuation gate
- **D-06:** CLI `--open-session` must refuse restore and exit non-zero when verification status is not `complete`, matching API 409 behavior.

### Async retrieval indexing (RETR-02)
- **D-07:** Remove synchronous `rebuild()` from `SemanticMemoryIndex.search()` hot path. Return empty/degraded when index is stale.
- **D-08:** Schedule background rebuild after memory writes (`appendEpisodic`, successful `patchScope`) via fire-and-forget `enqueueRebuild()`.

### Claude's Discretion
Implementation module layout, exact bundle schema versioning, and test placement at Claude's discretion following existing adapter patterns.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `FileSessionStore` already persists memory/preferences/vectorIndex section files.
- `MemoryResolver.inspect()` returns full memory snapshot for API/UI.
- `FileMemoryStore.listScopes/listEpisodic` provide export source data.

### Established Patterns
- Session bundles use versioned section envelopes via `FileSessionStore.save()`.
- API open path already blocks non-complete verification with 409.
- Memory store uses sessionId as runId throughout runtime.

### Integration Points
- `savedSessionPayload()` must become async and accept memory dependencies.
- `startControlServer` open handler must restore memory after graph restore.
- `index.ts` UI boot must derive runId from saved bundle when `--open-session` is used.
