# Phase 27-01 Plan: Memory Preferences and Inspection Surfaces

## Goal

Expose structured memory and preferences through CLI, API, and UI while preserving audited local-first behavior.

## Tasks

### Task 1: Cross-Run Preference Scopes

Files:
- `src/ports/memory-store-port.ts`
- `src/adapters/file-memory-store.ts`
- `src/application/memory-resolver.ts`

Steps:
1. Add memory inspection methods for scopes, episodic entries, packet metadata, and audit records.
2. Support `project` and `permanent` lifetime scope paths that can be read across runs.
3. Treat `project-preferences` as the default project-level preference scope.
4. Support audited preference deletion through patch tombstones.

### Task 2: CLI and API Surfaces

Files:
- `src/cli/args.ts`
- `src/index.ts`
- `src/application/control-server.ts`

Steps:
1. Add CLI flags to inspect memory and set/delete project preferences.
2. Add API endpoints for memory inspection and preference mutation.
3. Ensure API responses include degraded/audit/provenance details.

### Task 3: UI Inspection Surface

Files:
- `ui/src/main.tsx`
- `ui/src/styles.css`

Steps:
1. Add an inspector panel for scopes, episodic summaries, packets, and audit records.
2. Add controls to create/update/delete project preferences.
3. Show degraded or rejected state inline.

### Task 4: Tests and Verification

Files:
- `tests/memory-store.test.ts`
- `tests/recursive-language-model.test.ts`

Steps:
1. Test project preferences survive across run ids.
2. Test preference set/delete audit behavior.
3. Test API inspection and mutation endpoints.
4. Run build, UI build, focused tests, and full test suite.

## Verification Commands
