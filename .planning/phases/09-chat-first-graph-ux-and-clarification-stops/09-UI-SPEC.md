## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Confirm graph and run |
| Empty state heading | Start by describing what you want to build |
| Empty state body | Send a message to create the first graph node. You can refine nodes before running. |
| Error state | We could not apply that graph change. Review the reason and try a more specific edit. |
| Destructive confirmation | Abort run: This stops the active run and keeps a checkpoint snapshot for resume. |

## Interaction Contract

### Draft vs Ready
- Graph remains in draft until user explicitly activates **Confirm graph and run**.
- While draft, run control is disabled and must display reason text describing missing readiness conditions.

### Message-to-Graph Mutation Flow
- Every proposed mutation is previewed inline in chat before apply.
- Ambiguous requests must trigger a clarification question before any mutation.
- Node targeting uses label/name; collisions require a disambiguation prompt.
- Dependency-impacting delete must block and offer explicit choices:
  - delete subtree
  - rewire dependents

### Clarification Stop Behavior
- Runtime clarification prompts are hard-blocking.
- Allowed actions at clarification stop: answer and continue, or abort.
- Skip/dismiss is not allowed.

### Clarification History Visibility
- Clarification question/answer entries must appear in both:
  - UI run history timeline
  - CLI `--json-stream` events
- Minimum fields per record:
  - `question_id`
  - `node_id`
  - `prompt_text`
  - `user_answer`
  - `asked_at`
  - `answered_at`
  - `resume_event_id`
