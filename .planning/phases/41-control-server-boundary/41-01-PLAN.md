# Phase 41 Plan 01: Control-Server Boundary

## Objective

Factor `src/application/control-server.ts` into `application/control-server/` with handlers grouped by HTTP surface while preserving endpoint paths, JSON shapes, status codes, and error strings. Compose `startControlServer` inputs from bootstrap `RuntimeContext` fields plus UI-mode extras via a dedicated builder — no dependency construction inside route handlers.

## Current state

- Single file `control-server.ts` (~823 LOC): `routeRequest` multiplexes every method/path, inline helpers (`sendJson`, `readJsonBody`, SSE, static UI).
- UI mode (`cli/run-modes/ui.ts`) builds `SessionRuntimeRef` and calls `startControlServer` with `projectRoot`, `sessionStore`, `memory`, etc.

## Target layout

| Area | Module |
|------|--------|
| Entry + server listen | `control-server/index.ts` |
| Public types | `control-server/types.ts` |
| Injected deps bag for routing | `control-server/control-server-deps.ts` |
| HTTP helpers | `control-server/http-utils.ts` |
| Dispatch | `control-server/route-request.ts` |
| Session + memory + saved sessions + SSE + chat + stop + approvals + clarifications | `control-server/handlers/session.ts` |
| Graph snapshot + layout + viewport + node mutation/plan/chat graph ops | `control-server/handlers/graph.ts` |
| Graph workflow list/export/import | `control-server/handlers/workflows.ts` |
| Model library | `control-server/handlers/model-library.ts` |
| Static UI fallback | `control-server/handlers/static-ui.ts` |
| Bootstrap-facing input builder | `control-server/start-input-from-bootstrap.ts` |

## Tasks

### 1. Planning artifact (this file)

Committed as executable boundary for CTRL/REG scope.

### 2. Extract modules and wire dispatch

- Move types and helpers; split `routeRequest` into surface handlers returning `handled: boolean`.
- Preserve global `try/catch` mutation error mapping and status heuristics in the dispatcher (`route-request.ts`).
- Remove flat `application/control-server.ts`; use `application/control-server/index.ts` (NodeNext resolves `control-server.js` → package root).

### 3. Bootstrap composition

- Add `buildStartControlServerInput(ctx, extras)` assembling `sessionStore`, `projectRoot` from `RuntimeContext` and passing through UI-provided session, memory, runners, ports.
- Slim `runUiMode` to use the builder (no behavioral change).

### 4. Verification

- `npm run check` green; full test count unchanged modulo structural moves.

## Success criteria

- CTRL-01..04 and REG-01..02 satisfied per phase context (`41-CONTEXT.md`).
- No API or UI contract drift.

## Threat / scope

Transport-only: handlers delegate to `InteractiveExecutionSession`, stores, `ModelLibraryService` — no new business logic.
