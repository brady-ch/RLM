<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/YAML -> runtime config | User-controlled CLI args and YAML values become execution bounds. |
| Runtime config -> domain loop state | Config values determine whether the domain runtime starts iterative model calls. |
| Domain metadata -> UI/CLI consumers | Metadata must be bounded, typed, and explicit so consumers do not infer silent outcomes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | T/D | `src/application/project-config.ts` | mitigate | Validate `runtime.qualityLoop.maxIterations` with `z.number().int().positive()` and default to 3 so invalid loop bounds cannot enter runtime config. |
| T-12-02 | D | `src/cli/args.ts` | mitigate | Parse `--quality-loop-max-iterations` with `parsePositiveInteger` and opt in only through explicit `--quality-loop` or max-iteration flag. |
| T-12-03 | R/I | `src/domain/types.ts` | mitigate | Encode terminal `QualityLoopStopReason`, `QualityLoopUsageSummary`, and `QualityLoopMetadata` as typed canonical metadata rather than trace-only strings. |
| T-12-04 | D/I | `src/domain/types.ts` | mitigate | Store candidate summaries and optional artifact refs in `QualityLoopCandidateSummary`; do not require full candidate text in graph metadata. |
| T-12-05 | R | non-loop config path | mitigate | Keep `qualityLoop.enabled` default false in config and CLI defaults so non-loop behavior remains unchanged unless explicitly configured. |
</threat_model>
