<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Config -> recursive runtime | Loop config controls iterative model calls and must be bounded. |
| Runtime -> language model | Each loop phase consumes model calls and token budget. |
| Runtime -> graph metadata | Internal loop state must not expand into top-level graph nodes or lose terminal semantics. |
| Runtime metadata -> CLI/JSON | Consumers must see explicit stop reasons and usage instead of inferred success/failure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-06 | D | `runQualityLoop` | mitigate | Preflight `remainingModelCalls() >= 5` before every iteration and stop with `budget_exhausted` before creating partial iteration records. |
| T-12-07 | R/I | `finishQualityLoop` helper | mitigate | Use one terminal helper that requires `stopReason` and writes usage to `this.metadata.qualityLoop` and `node.loop`. |
| T-12-08 | I | `ExecutionGraphNode.loop` | mitigate | Store phase records and candidate summaries under one `"quality-loop"` node; tests assert graph node count remains 1. |
| T-12-09 | D/I | loop candidate metadata | mitigate | Persist concise summaries and optional artifact refs, not full candidate text, in graph metadata. |
| T-12-10 | R | non-loop runtime path | mitigate | Branch on `config.qualityLoop?.enabled === true` only; tests assert disabled loop keeps direct trace `["answer"]`. |
| T-12-11 | R/I | `src/cli/render.ts` | mitigate | Render explicit `qualityLoop.stopReason`, selected candidate id, iteration count, and usage in compact/JSON output when present. |
</threat_model>
