<decisions>
## Implementation Decisions

### Route Porting Strategy
- Port missing routes to `crates/rlm-core/src/control_server/routes.rs` matching TS handler semantics in `src/application/control-server/handlers/session.ts`
- Preserve status codes and error vocabulary: 404 when stores unconfigured, 409 on unsafe session reopen when verification !== complete
- Use existing `FileSessionStore`, `FileMemoryStore`, `RouterState` session runtime fields — do not reimplement stores

### Session Save/Reopen (PERS-01, REG-01, VIDX-02)
- Wire `POST /api/saved-sessions/save`, `GET /api/saved-sessions/{id}`, `POST /api/saved-sessions/{id}/open`
- On save: use `session_memory_bridge` helpers to export live memory + vector records into payload (mirror TS `buildSavedSessionPayload`)
- On open: call `restoreSessionMemory` equivalent — rebind runId, restore memory scopes/episodic, merge vector records via `merge_session_vector_records`
- Block reopen when `saved.verification.status !== "complete"` with 409 + savedSession in body

### Memory Preferences (PERS-02)
- Wire `POST /api/memory/preferences` (body: key, value, lifetime) and `DELETE /api/memory/preferences/{key}`
- Return updated inspect payload after mutation (same as TS)

### Chat & Clarification (ENGN-02, GRPH-02)
- Wire `POST /api/chat/message`, `POST /api/chat/apply`, `POST /api/chat/cancel`
- Wire `POST /api/clarifications/abort`
- Fix `chat_confirm_run` to read request body: `variant` (pipeline|playbook), `input` string; apply pipeline template when variant=pipeline and input non-empty

### Run-State (PERS-03)
- Wire `FileRunStateStore` into graph executor checkpoint/resume if feasible within phase scope
- If not feasible in one plan wave: document explicit deferral in 60.1-VERIFICATION.md with rationale — do not silently skip

### Verification Backfill
- Create `53-VERIFICATION.md`, `54-VERIFICATION.md`, `55-VERIFICATION.md`, `56-VERIFICATION.md` after corresponding wiring lands
- Sync REQUIREMENTS.md checkboxes for reqs with passing evidence

### Testing
- Extend Rust integration tests in `crates/rlm-core/tests/` covering save/open/preferences routes
- Reuse or port patterns from `tests/domain/recursion/recursive-language-model.test.ts` session/memory route tests
- `npm run check:rust` must pass

### Claude's Discretion
- Exact Rust module split for handler extraction (inline vs `handlers/` submodule)
- Whether run-state wiring is one plan or deferred sub-plan
- Parity fixture updates for new routes

</decisions>
