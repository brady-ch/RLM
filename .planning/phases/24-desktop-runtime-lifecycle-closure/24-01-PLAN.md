# Phase 24-01 Plan: Native Desktop Runtime Lifecycle Closure

## Goal

Make the desktop app path own the runtime lifecycle instead of only staging release files: native launch should start the RLM control server, integrate Ollama readiness, clean up managed children on quit, and produce honest packaging/smoke evidence.

## Tasks

1. Define the desktop runtime contract.
   - Add a machine-readable desktop manifest field for runtime mode, required sidecars, UI URL strategy, and Ollama policy.
   - Document which processes are RLM-managed versus user-managed.

2. Add a native shell backend lifecycle.
   - Extend `src-tauri/src/main.rs` to start the packaged RLM runtime on app setup.
   - Capture the selected localhost UI URL and navigate the webview to it.
   - Stop the RLM-managed child process on app exit.
   - Preserve user-managed Ollama by tracking only children started by the app.

3. Add no-Node launch packaging.
   - Choose and implement one packaging strategy for the RLM sidecar:
     - bundled Node runtime plus compiled JS, or
     - single-file Node executable sidecar, or
     - Rust-native control-server migration for the desktop path.
   - Update `scripts/packaging/build-release.mjs` and smoke checks to fail when the selected sidecar is missing.

4. Integrate Ollama readiness into first launch.
   - Run readiness before exposing the model library as ready.
   - Surface explicit UI/API status for unavailable Ollama, managed-start failed, and user-managed endpoint detected.
   - Do not kill a user-managed Ollama process on app quit.

5. Verify native and clean-machine paths.
   - Run `npm run build`, `npm run build:ui`, `npm run package:smoke`, and `npm test`.
   - Run `npm run tauri:build` where platform dependencies are available.
   - Record any platform dependency blocker exactly.
   - Add or document a clean-machine smoke path: launch app, see model library, install curated model, run workflow.

## Acceptance Criteria

- PROD-01 can be checked complete only when native launch no longer requires user-installed Node/npm.
- PROD-02 can be checked complete only when the Tauri shell starts and stops the RLM-managed control server.
- PROD-03 can be checked complete only when Ollama readiness is integrated into the native first-launch path.
- If cross-OS packaging cannot be fully run in this environment, the verification artifact must separate proven results from deferred platform validation.
