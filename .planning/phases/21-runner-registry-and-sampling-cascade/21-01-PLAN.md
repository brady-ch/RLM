# Phase 21-01 Plan: Runner Registry and Sampling Cascade

## Goal

Implement the adapter-backed runner and sampling cascade foundation for v1.3 without breaking existing CLI/YAML model routing.

## Scope

In scope:

- Sampling type contract on model complete options and responses.
- Project config schema for global sampling defaults and per-model profiles.
- Cascade resolver with source-layer metadata.
- Node-level sampling override metadata and API.
- Minimal UI inspector/settings controls.
- Ollama and HTTP adapter support/warning behavior.
- Tests and render metadata proving precedence and visibility.

Out of scope:

- Full model library UI and downloads.
- Tauri shell and installers.
- New llama.cpp/vLLM adapters.
- Store distribution or auto-update.

## Tasks

### Task 1: Add Sampling Types and Config

Files:

- `src/ports/language-model-port.ts`
- `src/application/project-config.ts`
- `tests/project-config-scopes.test.ts`

Steps:

1. Add `LanguageModelSamplingOptions` with optional `temperature`, `topP`, `topK`, `repeatPenalty`, `maxTokens`, and `seed`.
2. Add effective sampling/source metadata types.
3. Add optional `sampling` to `LanguageModelCompleteOptions`.
4. Add optional project config for global defaults and per-model profiles.
5. Keep all new config optional/defaulted so older YAML parses unchanged.
6. Add tests for default parsing and sampling config parsing.

### Task 2: Implement Cascade Resolution

Files:

- `src/application/model-provider.ts`
- `src/domain/types.ts`
- `src/domain/recursive-language-model.ts`
- `tests/recursive-language-model.test.ts`

Steps:

1. Add a resolver that merges adapter defaults, global defaults, model profile, and node override.
2. Preserve precedence: node > model profile > global > adapter default.
3. Attach effective sampling metadata and source layer to completion response and graph node metadata.
4. Ensure purpose routing, model override, and quality-loop phase model routing still use the selected model before resolving model-profile sampling.
5. Add fake-model tests proving precedence and metadata propagation.

### Task 3: Wire Adapters and Unsupported Metadata

Files:

- `src/adapters/ollama-language-model.ts`
- `src/adapters/http-language-model.ts`
- `src/application/runtime-composition.ts`
- `tests/recursive-language-model.test.ts`

Steps:

1. Pass supported sampling options to Ollama completion calls.
2. Forward sampling to HTTP adapter payloads.
3. Report unsupported or ignored sampling fields via response warnings/degraded metadata.
4. Preserve existing constrained tool-calling behavior.

### Task 4: Add Node API and Minimal UI

Files:

- `src/application/execution-controller.ts`
- `src/application/control-server.ts`
- `ui/src/main.tsx`
- `src/cli/render.ts`
- `tests/recursive-language-model.test.ts`

Steps:

1. Add node sampling override fields to graph node state.
2. Add control-server endpoint to set/clear sampling overrides.
3. Add compact UI inspector controls for temperature/top-p/max tokens at minimum, with room for the full first-pass fields.
4. Show effective sampling values and source layer in node inspector and CLI render output.
5. Add source-level UI/API tests proving controls and metadata are present.

## Risks and Mitigations

- Existing uncommitted edits touch overlapping runtime/UI files. Read and preserve current file contents before editing.
- Provider sampling support varies. Represent unsupported fields explicitly instead of silently dropping them.
- UI scope can expand quickly. Keep Phase 21 controls minimal and leave catalog/profile UX depth to Phase 22.
