# Phase 25-01 Plan: Session Snapshot Store

## Goal

Implement durable saved-session bundles for interactive workflow sessions, with CLI/API/UI entry points and strict restore verification. Phase 25 must reserve structured memory, preferences, and vector retrieval/index sections in the snapshot contract so later phases cannot lose them.

## Tasks

### Task 1: Session Store Port and File Adapter

Files:
- `src/ports/session-store-port.ts`
- `src/adapters/file-session-store.ts`

Steps:
1. Define saved-session manifest, section status, restore verification, and section payload types.
2. Implement `.rlm/sessions/<session-id>/` directory bundles with `manifest.json` plus section files.
3. Include schema-versioned sections for graph/session state, run-state, artifact refs, structured memory metadata, preferences metadata, and vector index metadata.
4. Use atomic temp-file writes and preserve corrupt files on verification failure.

### Task 2: Session Snapshot Service and UI Session Rehydration

Files:
- `src/application/session-snapshot-service.ts`
- `src/application/execution-controller.ts`

Steps:
1. Add service methods for save, list, inspect, and open.
2. Add an `InteractiveExecutionSession.restoreFromSnapshot` factory or equivalent import path.
3. Ensure reopened sessions restore graph, approvals, clarification state, viewport, run status, and safe continuation metadata.
4. Block unsafe continuation when restore verification is degraded or failed.

### Task 3: Control Server and CLI Entry Points

Files:
- `src/application/control-server.ts`
- `src/index.ts`
- `src/cli/args.ts`
- `src/cli/render.ts`

Steps:
1. Add API endpoints for saved-session list/save/open/inspect.
2. Wire a file session store in UI mode using `.rlm/sessions`.
3. Add CLI options for listing and inspecting saved sessions, and for opening a session in UI mode.
4. Render complete/degraded/failed restore verification clearly.

### Task 4: UI Save/Reopen Controls

Files:
- `ui/src/main.tsx`
- `ui/src/styles.css`

Steps:
1. Add compact save/open controls to the inspector.
2. Show autosave/manual save status and session metadata.
3. Show restore section status for graph, run-state, artifacts, memory contract, preferences contract, and vector contract.
4. Use degraded/error states that block unsafe continue actions.

### Task 5: Tests and Verification

Files:
- `tests/session-store.test.ts`
- `tests/recursive-language-model.test.ts`

Steps:
1. Test file bundle save/list/load/verify, including missing and corrupt sections.
2. Test control-server session persistence APIs.
3. Test reopened session snapshot preserves graph/clarification state.
4. Run build, UI build, focused tests, and full test suite.
