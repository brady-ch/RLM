    Create `src/application/graph-planner.ts` exporting:

    ```typescript
    export interface PlannedChildSpec {
      label: string;
      prompt: string;
      type: ComposerNodeType;
      complexity: ComposerComplexity;
    }
    export interface GraphPlannerContext {
      nodeId: string;
      nodeLabel: string;
      nodePrompt: string;
      ancestors: Array<{ id: string; label: string; prompt: string }>;
      maxChildren: number;
    }
    export interface PlanChildrenResult {
      children: PlannedChildSpec[];
      diagnostics: { purpose: "plan"; model?: string; validationError?: string };
    }
    export class GraphPlannerError extends Error {
      constructor(public readonly code: "planning_failed" | "invalid_planner_output", message: string, public readonly details?: string);
    }
    export async function planChildren(model: LanguageModelPort, context: GraphPlannerContext): Promise<PlanChildrenResult>;
    ```

    Zod schema for model response:
    ```typescript
    z.object({ children: z.array(z.object({
      label: z.string().min(1),
      prompt: z.string().min(1),
      type: z.enum(["AI","Code","TTS","Splitter","Joiner","Validator"]),
      complexity: z.enum(["low","medium","high"]),
    })).min(1) })
    ```

    Prompt design (Claude's discretion): system message instructs planner to return ONLY JSON `{ "children": [...] }` with at most `context.maxChildren` items; user message includes node prompt plus numbered ancestor chain (`ancestors` joined label+prompt).

    Parse model `response.content` using brace-slice JSON extraction (same approach as recursive-language-model). On zod failure → `GraphPlannerError("invalid_planner_output", ...)`. On model throw → `GraphPlannerError("planning_failed", ...)`.

    Call `model.complete(messages, { purpose: "plan" })`. Capture `response.model` in diagnostics.

    Optionally extend `NodeComposer` in `src/domain/types.ts` with `plannedBy?: "model" | "user"` for replan tracking (used in plan 02).

    2. Mock model returning `{not json}` → invalid_planner_output
    3. Mock model throwing → planning_failed
    4. Context with 2 ancestors → complete() messages include both ancestor labels
