# Phase 8.5: Typed Artifact + Stateful Workflow Runtime - Context

**Gathered:** 2026-05-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver typed artifact contracts and a guarded external run-state runtime for long-running, model-chained workflows, including code-only nodes, optimistic concurrency, path-level ACL, and auditability/replay semantics (ARTF-01).

</domain>

<decisions>
## Implementation Decisions

### Artifact contract and validation model
- **D-08.5-01:** Use a hybrid contract model: node-level input/output artifact schemas are source-of-truth, with optional edge-level narrowing rules.
- **D-08.5-02:** Validation strictness is configurable per node, with default strict rejection.
- **D-08.5-03:** Edge schema rules may narrow node schemas but must never widen them.

### Run-state store boundary and persisted scope
- **D-08.5-04:** Implement a pluggable run-state store interface now, with a file-backed reference adapter in this phase.
- **D-08.5-05:** Persist "standard" scope: run metadata + node statuses + artifact refs, plus mutation log, checkpoint snapshots, and resume cursor.

### Concurrency and ACL policy
- **D-08.5-06:** Use reject-on-conflict optimistic concurrency (`version`/`etag` mismatch returns conflict and requires explicit retry).
- **D-08.5-07:** Use path-prefix ACL with per-node capability tokens for write authorization.

### Code-only node runtime model
- **D-08.5-08:** Keep code-only nodes in the same lifecycle model as other nodes and add a dedicated `code_execution` event subtype for observability.
- **D-08.5-09:** Sandbox policy is configurable with default subprocess isolation.

### Audit and replay contract
- **D-08.5-10:** Mutation audit payload level is core: actor, path, action, accepted/rejected decision, reason, timestamp, and sequence.
- **D-08.5-11:** Replay target is operational replay (reconstruct run decisions/checkpoints, not full deterministic data replay).

### the agent's Discretion
- Exact schema DSL/type representation for node/edge contracts (Zod-first vs JSON-Schema-first) so long as hybrid precedence is enforced.
- Capability token lifecycle specifics (format, TTL, revocation timing) as long as path-level least privilege is preserved.
- Operational replay UX details in CLI/UI as long as audit core fields remain mandatory.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `src/domain/types.ts`: existing execution graph/event metadata structures can be extended for artifact schema refs, concurrency metadata, and replay handles.
- `src/application/execution-controller.ts`: established checkpoint token/version handling and mutation validation behavior that can anchor optimistic concurrency and ACL checks.
- `src/application/mcp-skill-runtime.ts`: existing sequence allocation and event sink composition patterns reusable for run-state mutation audit streams.
- `src/application/runtime-events.ts`: stable event id/fingerprint primitives reusable for state mutation records.

### Established Patterns
- Ports/adapters architecture is already used for host/tool integrations; run-state store should follow the same boundary pattern.
- Explicit failure and pause semantics are mandatory; no silent fallback is permitted.
- Structured event emission with severity/code/seq is an existing norm for diagnostics and recovery paths.

### Integration Points
- Introduce typed artifact contracts and boundary validation hooks in recursive execution flow.
- Add run-state store port + file adapter and wire it through application orchestration/session lifecycle.
- Surface concurrency conflicts, ACL denials, and mutation audit records through both CLI/JSON stream and control-server APIs.

</code_context>

<specifics>
## Specific Ideas

- Favor strict-by-default contracts while allowing explicit per-node flexibility where needed.
- Keep runtime semantics unified across model and code-only nodes to avoid branching execution logic.

</specifics>
