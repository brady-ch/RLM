## Integration & flows

Cross-phase plugin manager wiring verified:

1. **CLI → Registry:** `src/cli/run-modes/plugin-commands.ts` uses `createPluginRegistryService` for list/install/enable/disable/uninstall/doctor/inspect/validate.
2. **Control-server → Registry:** `src/cli/run-modes/ui.ts` injects same service into control-server deps; `handlers/plugins.ts` exposes `/api/plugins/*`.
3. **Registry → Catalog:** User catalog at `~/.rlm/plugins/` with `catalog.json`; install writes atomically; doctor validates manifests/paths.
4. **Runtime → Loader:** `build-runtime-context.ts` uses `PluginLoader` with user + project catalogs; builtins discovered from `src/plugins/builtin/`.
5. **UI → API:** `ui/src/main.tsx` PluginPanel consumes list/doctor/install/enable/disable/uninstall routes; restart banner on `requiresRestart: true`.

**E2E flow:** User installs plugin via CLI or UI → catalog updated → doctor passes → runtime reload required → PluginLoader picks up on next session. No divergence between CLI and UI state surfaces.
